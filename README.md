# Lovely | Functional portfolio project

مشروع معرض أعمال غير تجاري لتأجير الفساتين، مبني من الصفر باستخدام Next.js وTailwind CSS وSupabase وshadcn/ui. الإصدار 0.16.1. الداتا والصور والعمليات مصطنعة، ولا يوجد دفع إلكتروني أو التزام بمال حقيقي. الهدف تجربة وظائف محفوظة فعلًا، لا واجهة ساكنة فقط.

المشروع مصمم للاستخدام التجريبي الخفيف على الخطط المجانية، دون اشتراط ترقية. يقبل المالك توقف Supabase عند عدم النشاط. لا يغيّر هذا المصدر حماية الاستضافة أو جمهور الموقع، ولا ينشئ حساب ضيف أو ينشر كلمات مرور.

## التشغيل المحلي

المطلوب Node.js 22.x وnpm. استخدم `.nvmrc` ثم:

```bash
npm ci
cp .env.example .env.local
npm run dev
```

دون إعداد Supabase، يعمل كتالوج مصطنع ومعاينات `/demo`. لا تتحول هذه المعاينات إلى قاعدة بيانات. مع الإعداد الصحيح، `/workspace` مساحة محفوظة حقيقية تتطلب حساب فريق نشطًا.

## ما يعمل

- كتالوج عربي RTL متجاوب، بحث وتصنيفات وحالة عرض وتفاصيل وصور. لا أسعار أو بيانات عملاء للزائر.
- Supabase Auth وSSR، تحقق من الحساب والدور على الخادم، وRLS. لا تسجيل عام من الواجهة.
- إضافة وتحرير وأرشفة واستعادة الفساتين والتصنيفات للأدمن.
- رفع الصور مع التحقق وإعادة الترميز WebP وإزالة EXIF. ترتيب محفوظ، وصورة رئيسية، وحذف مؤكد مع سجل تنظيف قابل لإعادة المحاولة وبديل عند غياب الصور.
- حجز ومقدم في معاملة واحدة. التواريخ أيام حسب `Africa/Cairo`، وقبل الخروج بيوم على الأقل. يوم تجهيز كامل بعد العودة، ومنع تعارض من PostgreSQL.
- سجل مبالغ بالقروش، منع تجاوز المستحق وتكرار الطلبات. هذه سجلات مصطنعة، وليست بوابة تحصيل.
- تسليم بالمقدم وتأكيد جاهزية وحالة ضمان فقط. لا رقم أو صورة بطاقة. العودة بعد اكتمال الرصيد ورد الضمان، وفحص سليم أو صيانة متعددة الأسباب.
- عمليات وتقويم، ولوحة أدمن، وإشعارات فعلية داخل الموقع. علامة القراءة لا تُخفي مشكلة ما زالت قائمة. أثر العودة المتأخرة تنبيه مهم للأدمن، لا إلغاء أو تحريك تلقائي لحجز قائم.
- غرامة تأخير اختيارية يضيفها الأدمن، لا مبلغ آلي على كل تأخير.
- عملاء وسجل نشاط وفريق للقراءة بصلاحيات مقيدة. الموظف يرى حجوزاته أو المسندة له، لا مالية الأتيليه العامة.
- تقارير قبض وCSV للأدمن بفترات أيام مصر، بالقروش الصحيحة وحماية خلايا الصيغ. لا إرسال تلقائي للتقارير.
- وضع portfolio وظيفي على بيانات مصطنعة مسجلة. تجهيز سيناريو اليوم للأدمن، مع إسناده لموظف عند الحاجة، دون إضعاف قواعد الحجز العادي.

## تهيئة Supabase

1. أنشئ مشروعًا بالخطة المجانية إذا لم يكن لديك مشروع. لا يلزم مورد مدفوع.
2. ضع URL وPublishable Key في `.env.local`. لا تضع `service_role` أو كلمة مرور أو أي مفتاح سري في `NEXT_PUBLIC_` أو Git أو المحادثات.
3. طبّق ملفات `supabase/migrations/` الخمسة عشر بترتيب أسمائها. البداية لمشروع جديد فقط. لمشروع قائم طبّق المهاجرات الناقصة بعد التحقق من سجله، ولا تعِد ملفات سابقة عشوائيًا.
4. عطّل التسجيل العام من إعدادات Supabase Auth. أنشئ حسابي الاختبار من Authentication، ثم سجلي `profiles` بمعرفي Auth الصحيحين، مع `role='admin'` و`role='employee'`. لا توجد ترقية ذاتية للدور.
5. اضبط السياسات المؤكدة: `date_precision='day'` و`business_timezone='Africa/Cairo'` و`same_day_allowed=false`. وصف طريقة الاستلام اختياري. لا تفترض طريقة دفع حصرية.
6. لإنشاء مجموعة المراجعة المصطنعة لأول مرة فقط، اقرأ `supabase/demo/README.demo.md` وحدد حسابي الدور الصحيحين. الـseed صريح، ليس مهاجرة تلقائية، ويتطلب بوابة تشغيل مغلقة. لا تعِد الـseed على بيانات محفظة اختبارات متنامية، ولا تعطل الحماية لتجاوز حراسه.

## تفعيل الاختبار الوظيفي المصطنع

المهاجرة 14 لا تفتح أي بوابة وحدها. بعد تطبيقها واختبارها على مشروع الداتا المصطنعة، وتطبيق المهاجرة 15 التي تقفل تعديل الإعدادات من حسابات التطبيق:

- اترك `ATELIER_PROTOTYPE_MODE=true` في البناء والتشغيل. يبقى التنبيه الواضح و`noindex`، ولا يتغير جمهور الاستضافة.
- اضبط `NEXT_PUBLIC_FUNCTIONAL_PORTFOLIO=true` عند البناء والتشغيل، ثم أعد البناء والنشر.
- من حساب مالك القاعدة، وعلى مشروع الاختبار المقصود فقط، فعّل `settings.synthetic_test_enabled=true` و`settings.live_bookings_enabled=true` مع قيم أيام مصر المذكورة أعلاه.
- تحقّق أن حسابًا غير مخول لا يستطيع تغيير إعدادات القاعدة أو سجلات التسجيل المصطنع. حسابات التطبيق لا تملك هذا الحق.
- اختبر من حساب الأدمن والموظف والزائر قبل اعتبار الخدمة المستضافة مقبولة. نجاح الاختبارات المحلية وحده لا يثبت تكامل Supabase/Vercel.

تطابق إعداد التطبيق والقاعدة شرط للحفظ. في هذا الوضع، اسم العميل الجديد يبدأ بـ`اختبار `، ومعرفه غير القابل للاتصال يبدأ بـ`TEST-`، مثل `TEST-001`. السجلات الخمسة الأصلية تحتفظ بقيمها القديمة وتُسجل داخليًا كمصطنعة. لا توجد خانة يستطيع المستخدم تبديلها لتحويل سجل حقيقي إلى مصطنع.

من `/workspace/portfolio` أنشئ سيناريو مستقلًا للتسليم اليوم أو العودة أو التأخير. سيناريو التسليم سعره المصطنع 100 جنيه ومقدمه 25 جنيهًا. يمكن للموظف المسند له فتحه من حسابه وتجربة الدورة. التواريخ السابقة في هذه السيناريوهات تاريخ مفبرك معلن للاختبار، لا عمليات فعلية. لا تُعدّل مجموعة المراجعة الأصلية، ولا تسمح بالحجز العادي في اليوم نفسه. الفستان الجديد بلا صورة افتراضيًا؛ ارفع له صورة مولدة من حساب الأدمن عند الرغبة.

## حدود الأمان والبيانات

- `dress-images` للصور المصطنعة القابلة للعرض برابط، لا مستندات خاصة أو صور هويات.
- حذف Storage ليس جزءًا من SQL rollback. اختبر الحذف بملف جديد مستقل فقط. لا تختبره على الصور الأصلية بافتراض أن التراجع سيعيد الملف.
- لا يعتبر الحذف منتهيًا إلا بعد تحقق غياب الملف وإغلاق طلب التنظيف. قد تبقى نسخة مؤقتة في كاش رابط الصورة القديم.
- إذا تعذر تأكيد إدراج metadata بعد رفع صورة، لا نحذف الملف تلقائيًا: قد يكون الإدراج تم فعلًا رغم فقد الرد. نتحقق من الرابط؛ وعند الشك نحتفظ بالملف ونُظهر مسار المتابعة للأدمن. راجع الحالة قبل رفع نسخة أخرى أو تنظيف ملف يتيم يدويًا.
- لا حذف مباشر للدفعات أو سجل التدقيق من حسابات التطبيق. لا استرداد آلي، ولا إرسال واتساب أو بريد أو Push.
- الخطة المجانية ليست خطة نسخ احتياطي. إعداد نسخة يدوية وتجربة استعادتها ما زالا من العمل المتبقي، ولا يعد هذا المستودع بديلًا لنسخة قاعدة البيانات وStorage.

## المتبقي، لا يخفيه هذا الإصدار

إدارة حسابات الموظفين من الواجهة، تعديل وإلغاء الحجوزات بضوابطها وتسوية استثناءاتها، مراجعة التوفر المستقبلي والحالة التشغيلية، ونسخة احتياطية مع استعادة مجربة، والقبول المستضاف المتكامل لكل المسارات. المقدم غير مسترد، والقرار للأدمن؛ لا نخترع معالجة تلقائية للدفعات الزائدة. الجواب الأخير عن المقدم قبل العودة يحتاج مواءمة شاشة الدفعات الحالية في تحديث تالٍ. التفاصيل في `docs/DECISIONS.md`.

لا توجد حاجة لترقية الخطة لإنهاء هذه الوظائف التجريبية، ولا نختزلها إلى أزرار معطلة. مع ذلك، لا تدّعي هذه الحزمة أن كل الـMVP انتهى.

## التحقق

```bash
npm run lint
npm run typecheck
npm test
npm run test:db
npm run build
npm run test:e2e
```

اختبار القاعدة يشغل PostgreSQL مؤقتًا محليًا على المنفذ 55439، مع بدائل محلية لـAuth وStorage، ولا يتصل بالمشروع السحابي. اختبارات المتصفح تستخدم Chrome، ويمكن ضبط `CHROME_PATH`. راجع `docs/VERIFICATION.md` و`evidence/` لحدود الاختبارات والصور الفعلية. الإصدارات الدقيقة في `package-lock.json`، وتثبيت `npm ci` يعيد نفس الرسم الاعتمادي.

## تصحيح أمان 0.16.1

لا تُفعّل بوابات الاختبار على 0.16.0 وحده. المهاجرة 15 تسحب كل منح تعديل settings من أدوار التطبيق، وتستبدل سياسة الأدمن العامة بقراءة فقط. حساب الأدمن داخل الموقع ليس مالك قاعدة البيانات، ولا يستطيع تعطيل القيد المصطنع أو فتح بوابة التشغيل أو تغيير يوم الحجز. إعداد التثبيت من حساب مالك القاعدة فقط. تُطبق 15 وحدها فوق 14، دون إعادة المهاجرات السابقة أو إعادة الـseed.
